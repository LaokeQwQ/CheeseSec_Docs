This guide covers Linux physical servers, cloud instances, and virtual machines. The online installer selects a language, detects the CPU architecture, downloads the latest stable release, verifies it, installs the systemd service, and prints the first-setup URL. Use the offline path when the target host cannot reach GitHub.

## 1. One-line installation (recommended) {#one-click}

Copy and paste this command. The installer opens an interactive prompt for language selection and then downloads, verifies, and installs the matching server release:

```bash
curl -fsSL https://github.com/LaokeQwQ/CheeseWAF/releases/latest/download/install-linux.sh | sudo bash
```

When already running as `root`, omit `sudo`:

```bash
curl -fsSL https://github.com/LaokeQwQ/CheeseWAF/releases/latest/download/install-linux.sh | bash
```

The script reads language, install-root, and entry-name input from `/dev/tty`, so interactive answers are not consumed as script source. For unattended provisioning, set the documented `CHEESEWAF_*` environment variables and invoke the downloaded script; never put passwords or setup tokens in shell arguments or history.

During the interactive flow, choose an application install root after selecting the language. Entering `/opt/cheesewaf`, for example, places the binary, Web assets, runtime configuration, data, and logs under `bin/`, `web/`, `config/`, `data/`, and `logs/` beneath that root. Press Enter to keep the split FHS layout shown below. The systemd unit remains under `/etc/systemd/system` unless `CHEESEWAF_UNIT_DIR` is explicitly overridden.

For automation, set `CHEESEWAF_INSTALL_DIR` before invoking the installer. Individual `CHEESEWAF_PREFIX`, `CHEESEWAF_WEB_DIR`, `CHEESEWAF_CONFIG_DIR`, `CHEESEWAF_DATA_DIR`, and `CHEESEWAF_LOG_DIR` values take precedence for their respective paths:

```bash
curl -fsSL https://github.com/LaokeQwQ/CheeseWAF/releases/latest/download/install-linux.sh \
  | sudo env CHEESEWAF_INSTALL_DIR=/opt/cheesewaf bash
```

Install roots must be absolute dedicated directories whose path components contain only ASCII letters, digits, `.`, `_`, or `-`; shared system directories and paths containing shell metacharacters are rejected.

The installer will:

1. Ask for 中文 or English and check Linux, architecture, disk space, `curl`, `tar`, and `systemd` prerequisites.
2. Download the latest stable server archive from GitHub Releases and verify `SHA256SUMS` and its signature. A failed verification stops before installation or service startup.
3. Install the binary, Web Console, runtime configuration, and systemd unit, then create the non-login `cheesewaf` service account.
4. Generate an HTTPS management listener, a one-time setup token, and a safe entry path. The entry path accepts ASCII letters and digits only; a random value is generated by default, and a custom value is accepted only when it passes the same validation.
5. Start the service, check the listener and health state, and print the version, architecture, installation paths, service state, management URL, token lifetime, and next steps.

Save the complete setup URL printed at the end. The token is short-lived and is revoked immediately after first setup. Do not paste the complete URL into tickets, screenshots, shell history, or logs.

## 2. First setup and public entry {#first-setup}

During initialization, open the `https://` URL printed by the installer. The setup URL always uses the fixed `/setup` path:

```text
https://PUBLIC_IP:9443/setup#setup_token=ONE_TIME_TOKEN
```

`ONE_TIME_TOKEN` is the one-time bootstrap token. The browser reads the token from the URL fragment, clears it from the address bar, and sends it in the `X-CheeseWAF-Setup-Token` header. The token is never placed in query parameters, cookies, or `localStorage`.

After setup completes, open `https://PUBLIC_IP:9443/SECURITY_ENTRY`. The security entry contains ASCII letters and digits only; it is generated by default or accepted as a validated custom value. The entry endpoint signs an access Cookie and redirects to the login page. Keep the setup route and the post-setup security entry as separate paths.

The management plane uses HTTPS by default for this installation path. Restrict security groups, firewalls, and any reverse proxy to trusted administration networks before exposing port `9443` to the Internet. A locally generated certificate may cause a browser warning on first access; replace it with a trusted certificate for production use.

After setup completes, the bootstrap token is invalid. If the URL is lost before an administrator is created, reset it on the host:

```bash
sudo -u cheesewaf cheesewaf setup token reset
```

Use the new URL printed by the command. The old URL cannot be recovered.

## 3. Verify the installation {#verify}

```bash
systemctl status cheesewaf --no-pager
ss -ltnp | grep ':9443'
sudo journalctl -u cheesewaf -n 100 --no-pager
```

Confirm that the version and architecture match the target host and that the expected process owns the management port. After first setup, add the first protected site and configure the data-plane listener from the Console.

Default FHS paths:

| Path | Purpose |
| --- | --- |
| `/usr/local/bin/cheesewaf` | Main binary |
| `/usr/local/bin/waf-cli` | CLI symlink |
| `/usr/share/cheesewaf/web` | Web Console assets |
| `/etc/cheesewaf/cheesewaf.yaml` | Runtime configuration copy |
| `/var/lib/cheesewaf` | Data, certificates, and bootstrap state |
| `/var/log/cheesewaf` | Access and audit logs |

With `CHEESEWAF_INSTALL_DIR=/opt/cheesewaf`, the corresponding application paths are `/opt/cheesewaf/bin/cheesewaf`, `/opt/cheesewaf/web`, `/opt/cheesewaf/config/cheesewaf.yaml`, `/opt/cheesewaf/data`, and `/opt/cheesewaf/logs`.

## 4. Offline or manual installation {#offline}

On a connected machine, download the architecture-specific `.tar.gz`, `SHA256SUMS`, and signature files from [GitHub Releases](https://github.com/LaokeQwQ/CheeseWAF/releases), then transfer them to the target host. Verify the files in the download directory, extract the archive, and run the installer:

```bash
sha256sum --check SHA256SUMS --ignore-missing
tar -xzf cheesewaf-*-linux-*.tar.gz
cd cheesewaf-*-linux-*
sudo ./install-linux.sh
```

The offline script still asks for the language and entry path locally, generates the setup token, and starts the service; it does not attempt to download another release. On a host without systemd, copy the binary and `web/dist` into your process manager's paths and start the service there. Keep a runtime configuration copy and a dedicated data directory; never edit the tracked `configs/cheesewaf.yaml` template in place.

Do not use unverified binaries, third-party mirrors, or stale installer scripts. A complete Linux archive contains `cheesewaf`, Web assets, configuration templates, the systemd unit, and this installer; stop and download the archive again if any item is missing.
